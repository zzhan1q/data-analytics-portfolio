## Как считали

- В выборку входят обращения с `complaint_type = 'Street Condition'`, созданные с 1 января 2024 года включительно до 1 января 2025 года. Закрытие могло произойти и в 2025 году. В каталоге поле называется **Problem**, его имя в API осталось `complaint_type`.[1]
- В числителе — разница между `closed_date` и `created_date` от 0 до 168 часов включительно. Метки не содержат смещения часового пояса: сравниваем записанное местное время без поправки на переход на летнее время.[3]
- Знаменатель — все обращения группы. Пустая дата закрытия считается пропуском; неразбираемая дата и закрытие раньше создания — ошибкой. Обе группы остаются в знаменателе. `UNSPECIFIED` показана отдельно и входит в общий итог. Закрытие в 311 не означает, что проблема устранена.[1]

## Воспроизведение

Из папки проекта, Python 3 со стандартной библиотекой:

```sh
python3 -B analyze.py
python3 -B -m unittest discover -s tests -v
```

`analyze.py` загружает из SODA v2 только `borough`, `created_date`, `closed_date`. При недоступности основного API пробует представление `aqxm-wpww` с тем же фильтром; если оба запроса не срабатывают или ответы достигают лимита, делит окно дат пополам. Перед записью сверяет число строк по районам с отдельным агрегатным запросом. Для этого среза счётчики совпали и на базовом наборе, и на представлении.[1][2]

`analysis.sql` выполняется в SQLite в памяти и рассчитывает категории, количества и доли. На диск пишутся только `summary.csv` и `report.html`. Для пересчёта нужен интернет; отчёт открывается локально без сети и внешних ресурсов. При обновлении источника цифры могут измениться.
